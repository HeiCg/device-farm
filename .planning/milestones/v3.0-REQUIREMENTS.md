# Requirements: Device Farm v3.0 Spec-Driven Architecture

**Defined:** 2026-04-17
**Core Value:** QAs e pipelines CI conseguem rodar testes Maestro em emuladores gerenciados automaticamente e acompanhar a execucao em tempo real, com uma arquitetura que LLMs entendem e mantem.

## v1 Requirements

Requirements for milestone v3.0. Each maps to exactly one phase via Traceability (populated by roadmapper).

### SPEC — Zod em todos os boundaries

- [x] **SPEC-01**: Schemas Zod colocated por modulo (`schemas.ts` / `events.ts` / `api.ts`); nenhum pacote `/shared/schemas` global
- [x] **SPEC-02**: Fastify routes usam `.parse()`; WebSocket decoders e row decoders usam `.safeParse()` com canal de erro estruturado
- [x] **SPEC-03**: Tipos TS em todo boundary derivam de `z.infer<typeof X>`; lint/review impede re-declaracao de tipos de boundary
- [x] **SPEC-04**: Cada tabela Postgres tem row decoder Zod (`decodeJobRow(row): Job`) validado no limite DB→app; JSONB (`jobs.metadata`) round-trip testado
- [x] **SPEC-05**: Eventos polimorficos usam `z.discriminatedUnion("type", [...])` com payload narrowing automatico em subscribers
- [x] **SPEC-06**: `fastify-zod-openapi` instalado e gerando OpenAPI 3.1 spec automaticamente das rotas; spec commitada em `server/openapi.json` no build
- [x] **SPEC-07**: JSON Schema do protocolo WebSocket exportado em build (consumido por CLI Go + web)
- [x] **SPEC-08**: Envelopes de evento usam `.passthrough()`; regra documentada "so additive changes" para schemas de evento publicados
- [x] **SPEC-09**: IDs usam brand types (`z.string().uuid().brand<"JobId">()`, `...brand<"DeviceId">()`) impedindo mistura em parametros (resolve tech debt deviceName)
- [x] **SPEC-10**: Envelope de evento carrega campo `v: z.literal(1)`; discriminated union por versao preparada para migracao futura

### EVENTS — Bus tipado + padroes

- [x] **EVENTS-01**: Typed event bus wrapper sobre Node EventEmitter exportado por modulo; `bus.on(type, handler)` narrows payload via discriminated union
- [x] **EVENTS-02**: Todo evento usa envelope `{id, type, v, correlationId, causationId, occurredAt, payload}` em runtime; schema de envelope compartilhado
- [x] **EVENTS-03**: Nomes de evento seguem `noun.verbed` past-tense dotted (`job.completed`, `device.allocated`); lint rule impede imperativo
- [x] **EVENTS-04**: Payloads default sao thin (IDs + delta minimo); excecao documentada para eventos terminais
- [x] **EVENTS-05**: Regra explicita "sync bus = mesma request / cache / WS broadcast; pg-boss queue = tudo que retry, sobrevive crash, ou chama externo" documentada em `docs/adr/`
- [x] **EVENTS-06**: Subscribers sao idempotentes; identificam duplicatas via `eventId + operationKey`; testado em pelo menos 1 handler retriavel por modulo
- [x] **EVENTS-07**: Falhas de retry exaurido emitem evento terminal (`*.failed.retryExhausted`) persistido na tabela `events`
- [x] **EVENTS-08**: Emit helpers em `events.ts` (`jobEvents.completed(jobId, summary)`); chamadas diretas a `bus.emit()` fora de helpers proibidas por lint
- [x] **EVENTS-09**: Bridge bus→queue documentado como padrao (`bus.on('X', e => boss.send('Y', e.payload, {singletonKey}))`); implementado onde aplicavel
- [x] **EVENTS-10**: Saga orquestrada do job lifecycle (queued → allocated → running → completed → recording → webhook → cleanup) substitui calls imperativos no job-service; cada transicao emite evento

### QUEUE — pg-boss (substitui filas in-memory + node-cron)

- [x] **QUEUE-01**: pg-boss integrado como plugin Fastify (`server/queue/plugin.ts`); inicializacao + shutdown ordenados com db plugin; schema `pgboss` isolado
- [x] **QUEUE-02**: Named queues criadas: `job.execute`, `webhook.deliver`, `recording.upload`, `cleanup.run`, `pipeline.trigger`; payloads Zod-validados no producer e no consumer
- [x] **QUEUE-03**: `job.execute` e `recording.upload` usam `singletonKey` (jobId / recordingId) impedindo double-spawn de emulator
- [x] **QUEUE-04**: Retry policy por queue: exponential backoff, max retries configurado, `retryLimit: 1` para handlers com side-effect fisico (emulator boot)
- [x] **QUEUE-05**: DLQ pipeline: `boss.onComplete` transforma failed-after-max em evento terminal no bus + linha na tabela `events`; endpoint `GET /api/queue/dlq` lista itens
- [x] **QUEUE-06**: Cada modulo que produz/consome queue tem `queue.ts` colocated (`server/jobs/queue.ts`, `server/hooks/queue.ts` etc.)
- [x] **QUEUE-07**: Graceful shutdown: SIGTERM → `boss.stop({graceful: true})` via Fastify `onClose`; drain documentado
- [x] **QUEUE-08**: `node-cron` removido de `pipelines-plugin` e `lifecycle-plugin`; substituido por `boss.schedule()`; correlationId injetado em todo `boss.send()` via wrapper lendo da AsyncLocalStorage

### MOD — Convencoes de modulo LLM-first

- [x] **MOD-01**: Cada modulo em `server/` tem `MODULE.md` com secoes fixas: Purpose / Public API / Events Emitted / Events Consumed / Queue Produced / Queue Consumed / Invariants / Non-Goals / Dependencies
- [x] **MOD-02**: Cada modulo tem `index.ts` barrel exportando so API publica; `dependency-cruiser` configurado e rodando em CI impedindo deep imports
- [x] **MOD-03**: Cada modulo tem `events.ts` com schemas Zod, emit helpers tipados, e event name constants; sem logica de negocio
- [x] **MOD-04**: Testes seguem "tests-as-spec": describe blocks por evento/operacao; arquivos como `events.spec.ts`, `saga.spec.ts`, nao 1:1 com source
- [x] **MOD-05**: File naming: kebab-case, singular para conceitos (`schemas.ts`), plural para coletores (`handlers.ts`); convencao documentada em `docs/adr/ADR-002-file-naming.md`
- [x] **MOD-06**: Cada modulo expoe factory `createXModule(deps): XModule` com deps tipadas; Fastify plugin apenas wira: `fastify.decorate('x', createXModule({db, bus, boss, logger}))`
- [x] **MOD-07**: Logger por modulo via `logger.child({module: 'jobs'})`; correlationId automaticamente via pino binding + ALS
- [x] **MOD-08**: MODULE.md tem secao "Invariants" listando regras nao-violaveis (ex: "job nao transiciona de Completed para Running"); 1 teste por invariant
- [ ] **MOD-09**: MODULE.md inclui bloco de codigo runnable (exemplo de emit + subscribe); exemplos compilam em CI (typecheck dos snippets)
- [x] **MOD-10**: `docs/adr/` criado com ADR-001 documentando v3.0 (por que spec+event driven); formato NNN-slug.md fixado

### TRACE — Correlation IDs + tabela events

- [x] **TRACE-01**: Fastify `onRequest` hook le `X-Correlation-Id` do header; gera `crypto.randomUUID()` se ausente; retorna no response header
- [x] **TRACE-02**: AsyncLocalStorage propaga correlationId via `@fastify/request-context`; acessivel em qualquer ponto da request sem threading de parametro
- [x] **TRACE-03**: Toda linha de log (pino) inclui `correlationId` via request-scoped child logger
- [x] **TRACE-04**: Envelope de evento inclui `correlationId` lido da ALS no emit; producer nunca passa manual
- [x] **TRACE-05**: Wrapper `boss.send()` injeta correlationId no payload; consumer restaura ALS antes de rodar handler (resolve gotcha ALS-cross-queue)
- [x] **TRACE-06**: Toda mensagem WebSocket carrega `correlationId` no envelope; web UI linka message a log entry
- [x] **TRACE-07**: Tabela `events` criada via Drizzle migration: `id, event_type, event_version, correlation_id, causation_id, aggregate_type, aggregate_id, payload jsonb, occurred_at, actor`; indexes em correlation_id, event_type, occurred_at
- [x] **TRACE-08**: Bus middleware persiste em `events` APENAS eventos marcados `persisted: true` no schema; registry tipado enforce regra
- [x] **TRACE-09**: CausationId populado automaticamente via ALS (wrapper de subscriber seta "currentEventId", emit subsequente herda)
- [x] **TRACE-10**: Campo `actor` populado de contexto de auth (userId / apiKeyId / "system" / "cron") via ALS
- [ ] **TRACE-11**: `GET /api/events?correlationId=X` retorna arvore causal; rota validada com Zod + documentada em OpenAPI

### CLI — Go codegen + refactor

- [x] **CLI-01**: Build pipeline: Zod → OpenAPI 3.1 (via fastify-zod-openapi) → extrai `components.schemas` → `go-jsonschema` → `cli/internal/types/generated.go` commitado
- [x] **CLI-02**: Makefile `make types` regenera e falha se diff nao commitado; CI enforce
- [x] **CLI-03**: Discriminated unions documentadas em `cli/internal/types/unions.go` (mapping manual) — go-jsonschema nao cobre bem sum types
- [ ] **CLI-04**: `cli/cmd/*` (run, status, logs, devices, cancel, config, doctor, dependencies, pipelines) refatorados consumindo tipos gerados de `generated.go`
- [x] **CLI-05**: `Job.DeviceName` populado corretamente pelo server response; CLI status exibe nome legivel, nao UUID (resolve tech debt DEBT-02)

### WEB — Typed client + shared WS schemas

- [x] **WEB-01**: `openapi-typescript` gera `web/src/lib/api/generated-types.ts` do mesmo OpenAPI spec do CLI; commitado; CI enforce
- [ ] **WEB-02**: `web/src/lib/api/client.ts` migra para `openapi-fetch` consumindo tipos gerados; todas as chamadas HTTP tipadas end-to-end
- [ ] **WEB-03**: Schemas Zod de WS messages compartilhados server↔web (relative imports ou npm workspace); web faz `.safeParse()` em frames e drops malformados com log estruturado

### DEBT — Tech debt v2.0

- [x] **DEBT-01**: Operational dependencies resolvidas: `lifecycle-plugin` declara `dependencies: ['api-plugin']` se apropriado ou inverte; `@device-stream/*` publicado em registry privado (ou tarballs no repo) — `file:../device-stream` removido; `installSimCapture` funciona sem sibling repo
- [x] **DEBT-02**: `Job.DeviceName` existe no schema Zod, populado pelo server em todos os endpoints que retornam job; CLI mostra device name ao inves de UUID (coberto tambem por CLI-05)
- [x] **DEBT-03**: Nyquist validation roda em cada phase do v3.0 via hook em `/gsd:execute-phase`; baseline capturada antes de Phase 1; `nyquist_compliant: true` como success criterion obrigatorio

## Out of Scope

Explicit exclusions. Anti-features do research.

| Feature | Reason |
|---------|--------|
| Global `/schemas` package (todos os schemas em um diretorio) | Couples modulos; vira god module. Pilar de v3.0 e modulos auto-contidos. |
| Full event sourcing (estado derivado so de events) | Over-engineered para single-node. Mantem current-state tables + append-only events hibrido. |
| BullMQ / Redis queue | Projeto e Postgres-only por design; Redis adiciona dep operacional. pg-boss e suficiente para single-node <50 jobs/dia. |
| OpenTelemetry distributed tracing | Premature para single-node. Structured logs + events table cobrem use cases. |
| Choreographed sagas para job lifecycle | Debug nightmare; recording falha e ninguem sabe qual job. Saga orquestrada escolhida. |
| Emit eventos antes de commit de transacao | Dual-write classico: subscriber ve, tx rolls back, phantom event. Use `tx.afterCommit` ou outbox. |
| Persistir TODO evento do bus em `events` table | Bloat; signal drowns. Regra: business events = `persisted: true` explicit. |
| `export *` em barrels (index.ts) | Internal helpers leak, viram API de-facto publica. Exports nomeados. |
| Deep nested module directories (Clean Architecture layering `application/use-cases/commands`) | LLMs walk trees desnecessarias. Flat structure por modulo. |
| Decorator-based DI com reflection metadata (NestJS-style) | Runtime magic que LLMs nao tracam staticamente. Factories explicitas. |
| Zod schemas em args internos (nao-boundary) | TS ja checa; parse tem custo. Zod so em trust boundaries. |
| Fat events (entidade inteira no payload) default | Stale snapshot. Thin payload + re-fetch. Terminal events sao excecao. |
| OAuth SSO | Fora de v3.0 (era item do PROJECT.md para milestone futuro de auth). |
| Notificacoes Slack/email | Webhooks cobrem; Slack/email sao out-of-scope do projeto. |
