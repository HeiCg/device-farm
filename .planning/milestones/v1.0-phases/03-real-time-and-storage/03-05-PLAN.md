  <files>server/artifacts/artifact-plugin.ts, server/jobs/job-service.ts, server/streaming/websocket-plugin.ts, server/index.ts</files>
  <action>
1. Create `server/artifacts/artifact-plugin.ts` (Fastify plugin):
   - Instantiate and decorate: `artifactService`, `recordingService`, `screenshotService`, `logcatService`, `memoryService`
   - Dependencies: `['config-plugin', 'db-plugin', 'pool-plugin']`

2. Modify `server/jobs/job-service.ts` -- update `executeJob()` method to integrate Phase 3 services:

   The JobService constructor needs additional parameters: `jobBroadcaster`, `artifactService`, `recordingService`, `screenshotService`, `logcatService`, `memoryService`, `devicePreviewManager`. Accept them as an options object (second arg or named fields).

   In `executeJob(job, deviceId, signal)`:
   a. **Before Maestro spawn:**
      - `await artifactService.ensureJobDir(job.id)` -- create artifact directory
      - CRITICAL (per CONTEXT.md decision "capture via device-stream + ffmpeg pipe -- reuse the same stream"):
        Call `await devicePreviewManager.startPreview(deviceId, platform)` to begin the device-stream capture. This MUST happen before recording starts so frames are flowing.
      - Start recording: `const recordingPath = artifactService.getArtifactPath(job.id, 'recording.mp4'); const ffmpegWritable = recordingService.startRecording(job.id, recordingPath)`
      - Pipe device preview frames into ffmpeg: obtain the frame stream via `devicePreviewManager.getFrameStream(deviceId)` and pipe it into `ffmpegWritable` (the Writable returned by startRecording). This is the critical wiring that feeds captured frames to the ffmpeg encoder.
      - Start logcat (Android only): `logcatService.start(job.id, deviceId, artifactService.getArtifactPath(job.id, 'logcat.txt'), onLogcatLine)`
      - Start memory sampling (Android only): `memoryService.startSampling(job.id, deviceId, 5000, onMemorySample)`
      - Broadcast status: `jobBroadcaster.emit(job.id, { type: 'status', data: { status: 'running' }, timestamp })`

   b. **During Maestro execution:**
      - Update MaestroParser callbacks to broadcast events:
        - `onFlowStart`: emit `{ type: 'step', data: { flowName, status: 'running' } }`
        - `onFlowResult`: emit `{ type: 'step', data: { flowName, status, durationMs } }`. If status is 'Failed', capture screenshot: `screenshotService.capture(platform, deviceId, artifactService.getArtifactPath(job.id, \`screenshots/step-{index}.png\`))` -- fire-and-forget with .catch
        - `onCommandStatus`: emit `{ type: 'log', data: { line: \`{command} {status}\` } }`
      - Each stdout line: emit `{ type: 'log', data: { line } }`
      - Logcat onLine callback: emit `{ type: 'logcat', data: { line } }`
      - Memory onSample callback: emit `{ type: 'metrics', data: sample }`

   c. **After Maestro completes (in finally block, before device release):**
      - Stop recording: `await recordingService.stopRecording(job.id)`
      - Stop device preview: `await devicePreviewManager.stopPreview(deviceId)` -- stops the device-stream capture, must happen AFTER recording stops so ffmpeg gets all frames
      - Stop logcat: `logcatService.stop(job.id)`
      - Stop memory: `const { samples } = memoryService.stopSampling(job.id)`
      - Write memory JSON: `await memoryService.writeSamples(artifactService.getArtifactPath(job.id, 'memory.json'), samples)`
      - Save maestro.log: write rawOutput to `artifactService.getArtifactPath(job.id, 'maestro.log')`
      - Create artifact DB records for all files that exist (video, logcat, memory, log, screenshots)
      - Use `stat()` to get fileSizeBytes for each
      - Broadcast final status: `jobBroadcaster.emit(job.id, { type: 'status', data: { status: result.status } })`
      - Cleanup broadcaster buffer: `jobBroadcaster.cleanup(job.id)` (after a delay to allow late readers)

   d. **On cancel/timeout (before cleanup):**
      - `recordingService.killRecording(job.id)` -- force kill ffmpeg
      - `await devicePreviewManager.stopPreview(deviceId)` -- stop device-stream capture

3. Update `server/streaming/websocket-plugin.ts`:
   - Add device preview route: `GET /ws/devices/:id/preview` with `{ websocket: true }`
   - Subscribe to devicePreview manager, relay frames as JSON `{ type: 'frame', data: base64, timestamp }`
   - Throttle frames to max 10fps (use timestamp check, skip frames within 100ms of last sent)

   - In shutdown handler: stop device preview manager, stop lifecycle cron (Plan 06 will add this)

CRITICAL integration notes:

- Fire-and-forget for screenshot capture (don't block Maestro execution)
- Use existing patterns: pino child loggers, process group kill, async-mutex where needed
- The frame piping (devicePreviewManager.getFrameStream -> ffmpegWritable) is the key link that makes video recording work. Without it, ffmpeg receives no input and produces an empty/corrupt file.
