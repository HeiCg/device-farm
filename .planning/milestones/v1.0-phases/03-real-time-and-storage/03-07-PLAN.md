  <action>
Fix 32 tsc --noEmit errors across four test files. Two distinct patterns:

**Pattern A — Mock object type casts (artifact-routes.test.ts, routes.test.ts):**
Where mock objects are passed to `fastify.decorate()`, wrap with `as unknown as ConcreteClass`. For example:
```typescript
// Before:
fastify.decorate('jobService', { createJob: vi.fn(), ... });
// After:
fastify.decorate('jobService', { createJob: vi.fn(), ... } as unknown as JobService);
```

Apply this pattern for all mock decorations: JobService, PoolManager, Database (PostgresJsDatabase), ArtifactService, HealthChecker. Import the concrete types at the top of each test file if not already imported.

**Pattern B — pino Logger generic mismatch (recording-service.test.ts, screenshot-service.test.ts):**
Where `pino({ level: 'silent' })` is assigned to a typed variable or passed as argument, cast with `as unknown as pino.Logger`:
```typescript
// Before:
const logger: pino.Logger = pino({ level: 'silent' });
// After:
const logger = pino({ level: 'silent' }) as unknown as pino.Logger;
```

This is the established double-cast pattern from Phase 1 gap closure (01-05). The cast is safe because the runtime object IS a pino.Logger — the generic parameter mismatch is a TypeScript inference limitation with pino's complex generic signatures.
