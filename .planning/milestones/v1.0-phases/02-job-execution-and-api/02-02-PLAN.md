  <name>Task 2: Implement JobService, job plugin, and wire into buildApp</name>
  <files>server/jobs/job-service.ts, server/jobs/__tests__/job-service.test.ts, server/jobs/plugin.ts, server/index.ts</files>
  <behavior>
    - createJob(files, metadata, platform) validates metadata against schema, inserts job + files in DB, enqueues, triggers dispatch
    - createJob rejects with 429-equivalent when queue is full
    - createJob rejects with 400-equivalent when YAML is malformed or metadata fails schema validation
    - tryDispatch(platform) allocates device, marks running, starts execution in background
    - Dispatch is mutex-protected per platform to prevent double-allocation
    - cancelJob(jobId) removes from queue (if queued) or aborts running process (if running)
    - cancelJob saves partial results and releases device
    - getJob(jobId) returns job with steps from DB
    - Event-driven: onDeviceReleased(platform) triggers tryDispatch
  </behavior>
  <action>
    1. Create `server/jobs/job-service.ts`:
       - Import JobQueue, JobExecutor, MaestroParser, types, Mutex, Drizzle schema
       - Class JobService with constructor(pool: PoolManager, db: Database, config: AppConfig, logger: pino.Logger)
       - Internal state:
         - queues: Map<Platform, JobQueue> (android + ios)
         - dispatchMutex: Map<Platform, Mutex> (one per platform per RESEARCH pitfall 1)
         - runningJobs: Map<string, { abortController: AbortController, deviceId: string }> (for cancel)
         - executor: JobExecutor (created in constructor)
       - Method `async createJob(opts: { files, metadata, platform })`:
         - Validate metadata against config.job_metadata_schema: check required fields exist, check optional field types
         - If queue isFull(config.jobs.max_queue_size): throw error with code 'QUEUE_FULL'
         - Insert job row (status: 'queued') in DB, insert jobFiles rows
         - Create QueuedJob and enqueue
         - Call tryDispatch(platform) (don't await -- fire and forget with .catch)
         - Return the created job object
       - Method `private async tryDispatch(platform: Platform)`:
         - Wrapped in dispatchMutex for the platform
         - If queue is empty, return
         - Try pool.allocate(platform, queue.peek().id)
         - If no device available, return
         - Dequeue job
         - pool.markRunning(deviceId)
         - Update job in DB: status='running', deviceId, startedAt=now
         - Create AbortController, store in runningJobs map
         - Fire-and-forget: executeJob(job, deviceId, abortController.signal).catch(handleExecutionError)
       - Method `private async executeJob(job, deviceId, signal)`:
         - Write flow files to temp dir
         - Execute via JobExecutor
         - Update job in DB: status, finishedAt, resultSummary, maestroOutput
         - Insert jobSteps rows
         - Cleanup temp dir (after process exits)
         - Remove from runningJobs map
         - Release device via pool.release(deviceId)
         - Call tryDispatch(job.platform) to check queue for next job (event-driven dispatch on release)
       - Method `async cancelJob(jobId: string)`:
         - Check if in runningJobs map -> abort via AbortController, partial results saved by executor
         - Else check queues -> remove from queue, update DB status='cancelled'
         - If not found in either -> throw not found error
       - Method `async onDeviceReleased(platform: Platform)`: calls tryDispatch(platform)
       - Method `getQueueDepth(): { android: number, ios: number }` for health endpoint
       - Method `async shutdown()`: cancel all running jobs, clear queues
