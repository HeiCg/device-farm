  <name>Task 1: WebhookService, JUnit generator, and FlakyDetector with tests</name>

  <behavior>
    WebhookService:
    - deliver(url, payload) POSTs JSON to url with Content-Type application/json
    - deliver retries up to maxRetries on 5xx responses with exponential backoff + jitter
    - deliver does NOT retry on 4xx responses
    - deliver does NOT throw on total failure (logs error, returns void)
    - deliver respects AbortSignal.timeout(10000) per request
    - If config.webhooks.secret is set, adds X-Signature-256 header with HMAC-SHA256

    JUnit generator:
    - generateJUnitXML(job, steps) returns valid XML string with testsuites/testsuite/testcase structure
    - Passed steps produce self-closing testcase elements
    - Failed steps include failure element with message and type
    - Skipped steps include skipped element
    - escapeXml handles <, >, &, ", ' characters
    - Summary attributes (tests, failures, errors, skipped, time) are computed from steps
    - Empty steps array produces valid XML with 0 counts

    FlakyDetector:
    - getFlaky(windowSize=10) returns flows where pass rate is between 20%-80% in last N runs
    - A flow with 100% pass rate is NOT flaky
    - A flow with 0% pass rate is NOT flaky
    - A flow with 50% pass rate IS flaky
    - Returns flowName, totalRuns, passCount, failCount, passRate for each flaky flow
  </behavior>
  <action>
    1. Create server/reporting/webhook-service.ts:
       - Constructor takes logger (pino.Logger) and optional config ({ secret?, timeout_ms?, max_retries? })
       - deliver(url: string, payload: object): Promise<void>
       - Uses native fetch with AbortSignal.timeout
       - Exponential backoff: baseDelay * 2^attempt + random jitter (0 to 50% of delay)
       - If secret configured, compute HMAC-SHA256 of JSON body and add X-Signature-256 header
       - Never throws -- logs error on exhausted retries

    2. Create server/reporting/junit-generator.ts:
       - Pure function generateJUnitXML(job: { id: string }, steps: Array<{ flowName, status, durationMs, error }>): string
       - escapeXml(str: string): string -- handles & < > " '
       - Builds XML string manually (no library per research recommendation)
       - Groups by flow for testcase elements, uses status for pass/fail/skip elements
       - Duration in seconds (durationMs / 1000) with 3 decimal places

    3. Create server/reporting/flaky-detector.ts:
       - Constructor takes db (Database type) and logger
       - getFlaky(windowSize = 10): Promise<FlakyFlow[]>
       - SQL: select flowName, status from job_steps WHERE flowName IS NOT NULL, ORDER BY startedAt DESC
       - Group results by flowName in application code, take last windowSize per flow
       - Compute pass rate, filter for flows between FLAKY_MIN_RATE (0.2) and FLAKY_MAX_RATE (0.8)
       - Return: { flowName, totalRuns, passCount, failCount, passRate }[]
       - Add index on job_steps(flow_name, status) for performance (document in action, executor adds via raw SQL or drizzle)

    4. Write tests for all three services:
       - WebhookService: mock global.fetch, verify retry behavior, HMAC header
       - JUnit generator: snapshot-style tests with known inputs/outputs, XML escaping
       - FlakyDetector: mock DB, verify threshold logic with various pass rates
  </action>
