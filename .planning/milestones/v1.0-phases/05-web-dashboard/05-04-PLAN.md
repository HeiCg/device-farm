  <action>
1. **web/src/lib/ws/job-stream.ts**: WebSocket client for job streaming using Svelte 5 runes per research Pattern 4:
   - `createJobStream(jobId: string)` returns object with reactive getters:
     - `logs: LogData[]` ($state array, append on 'log' messages)
     - `steps: StepData[]` ($state array, append on 'step' messages)
     - `metrics: MetricsData[]` ($state array, append on 'metrics' messages)
     - `logcatLines: string[]` ($state array, append on 'logcat' messages)
     - `status: string | null` ($state, updated on 'status' messages)
     - `connected: boolean` ($state)
   - `connect()`: Creates WebSocket to `ws[s]://host/ws/jobs/{jobId}`, parses JSON messages, dispatches by type
   - `disconnect()`: Closes WS connection
   - On 'status' message with terminal status (passed/failed/cancelled/timeout): set status, auto-disconnect after 1 second (server may send final messages)
   - Reconnect logic: on unexpected close (not user-initiated), retry after 2s, max 3 attempts

2. **web/src/lib/ws/device-preview.ts**: WebSocket client for device screen preview:
   - `createDevicePreview(deviceId: string)` returns:
     - `frameSrc: string` ($state, set to `data:image/jpeg;base64,{data}` on each frame)
     - `connected: boolean` ($state)
   - `connect()` / `disconnect()` methods
   - Use single `<img>` src update pattern (research Pitfall 2): update frameSrc directly, browser handles rendering

3. **web/src/lib/components/jobs/LogViewer.svelte**: Log output viewer.
   - Props: `logs: LogData[]`
   - Renders log lines in a monospace container (bg-gray-900 text-green-400 font-mono text-sm)
   - Auto-scroll to bottom on new messages using `$effect` + `requestAnimationFrame` (per research example)
   - Max height with overflow-y auto (h-96 or h-[500px])
   - Show line count in header
   - Limit DOM rendering to last 1000 lines for performance (per research Pitfall 5)

4. **web/src/lib/components/jobs/StepList.svelte**: Structured test steps.
   - Props: `steps: StepData[]`
   - Render each step as a row: flow name, command (if not null), status badge (passed=green check, failed=red X, running=blue spinner, skipped=gray dash), duration
   - Use lucide-svelte icons: CheckCircle2, XCircle, Loader2 (with animate-spin), MinusCircle
   - Summary at top: total, passed, failed, skipped counts

5. **web/src/lib/components/devices/DevicePreview.svelte**: Live device screen.
   - Props: `deviceId: string`
   - Uses `createDevicePreview` to connect on mount, disconnect on destroy (via `onMount` return or `onDestroy`)
   - Renders frameSrc in `<img>` tag with aspect-[9/16] container
   - Shows "Connecting..." / "Waiting for frames..." states
   - Rounded corners, border

6. **web/src/lib/components/jobs/MetricsPanel.svelte**: Memory metrics.
   - Props: `metrics: MetricsData[]`
   - Display latest values: Total PSS, Native Heap, Java Heap in MB (divide by 1024)
   - Simple bar/progress visualization for each (Tailwind bg-blue-500 width based on percentage of max seen value)
   - Show trend: number of data points collected

7. **web/src/lib/components/jobs/LogcatPanel.svelte**: ADB logcat output.
   - Props: `lines: string[]`
   - Similar to LogViewer but with different styling (bg-gray-800, text-gray-300)
   - Auto-scroll, limit to last 500 lines in DOM
   - Monospace font

2. **web/src/routes/jobs/[id]/+page.svelte** (UI-03, UI-04, UI-07): The main job detail page with split view.

   **Data flow:**
   - Extract job ID from `$page.params.id`
   - On mount: fetch job details via `getJob(id)` and artifacts via `getJobArtifacts(id)`
   - If job status is 'running': connect `createJobStream(id)` for live updates
   - If job has a deviceId and status is 'running': connect `createDevicePreview(deviceId)` for live screen
   - When job stream reports terminal status: refetch job details and artifacts via REST (per research Pitfall 4)
   - On destroy / navigation: disconnect all WebSocket connections (per research Pitfall 1)

   **Layout (split view):**
   - Top bar: Job ID, StatusBadge, platform, created time, duration
   - Two-column split below (lg:grid-cols-2, stack on mobile):
     - **Left column**: Live preview (DevicePreview if running, VideoPlayer if completed with video artifact) + MetricsPanel below
     - **Right column**: Tabs for "Logs", "Steps", "Logcat"
       - Logs tab: LogViewer component with stream.logs
       - Steps tab: StepList component with stream.steps (or job.steps from REST if not running)
       - Logcat tab: LogcatPanel with stream.logcatLines

   **Tab implementation:** Simple $state variable for activeTab ('logs' | 'steps' | 'logcat'). Tab buttons with active indicator (border-bottom or bg change).

   **Conditional rendering:**
   - Running job: show DevicePreview + live WS data
   - Completed job: show VideoPlayer (if video artifact exists) + REST data (logs from getJobLogs, steps from job.steps)
   - Completed job without video: show StepList only in left column, expand right column
   - Find video artifact: `artifacts.find(a => a.type === 'video')`

   **WebSocket lifecycle:**
   - Use `onMount` for initial setup and WS connections
   - Return cleanup function from `onMount` (or use `onDestroy`) to call `disconnect()` on both WS clients
   - Watch for status changes: when stream.status becomes terminal, refetch REST data

Use `$state` for all reactive variables. Use `$derived` for computed values (e.g., `isRunning = $derived(job?.status === 'running')`). Use `$effect` for side effects (e.g., watching status changes to trigger refetch).
