    Write `docs/adr/001-spec-driven-architecture.md` starting from the EXACT outline in RESEARCH §11. The file MUST contain these four Nygard top-level sections in order:

    1. `## Status` — single line: `Accepted — 2026-04-17`.

    2. `## Context` — 2-3 paragraphs covering:
       - v2.0 shipped a working single-node test platform, but its codebase resists LLM comprehension and module-scale refactoring.
       - Specific problems: cross-module imperative calls (`jobService.executeJob` reaches directly into `recordingService`, `webhookService`, `broadcaster`), in-memory queues + `node-cron` split, no correlation IDs, Zod validation only at Fastify boundaries.
       - Team is 1 person + LLM assistants (Claude Code, Copilot); investment in LLM-assisted maintenance is load-bearing.

    3. `## Decision` — five locked pillars, each with a short prose paragraph:
       1. **Zod at every trust boundary** — API, WS frames, events, DB row decoders, config YAML. Types inferred via `z.infer`. Branded IDs (`JobId`, `DeviceId`, `PipelineId`, `ArtifactId`, `RecordingId`) in `server/types/ids.ts` prevent mixing at compile time.
       2. **In-process typed event bus per module** — `bus.on<T>(type, handler)` narrows via a registry. Synchronous; for same-request cache invalidation + WS broadcast. Enforced by `no-direct-bus-emit` lint rule.
       3. **pg-boss v12 as the single durable queue** — replaces in-memory queues and `node-cron` (v2 removed in Phase 18). **Rule (EVENTS-05):** *sync bus = same request / cache / WS broadcast; pg-boss queue = anything that retries, survives crash, or calls external*. Physical-side-effect handlers default to `retryLimit: 1` with `singletonKey`.
       4. **Correlation IDs + append-only `events` table** — `AsyncLocalStorage` via `@fastify/request-context` v6 stamps every log line + envelope. Persisted business events (flagged `persisted: true` in registry) land in `events` for causal-tree trace via `GET /api/events?correlationId=X` (Phase 27).
       5. **LLM-first modules** — each `server/<module>/` has `MODULE.md` + barrel `index.ts` + `events.ts` + factory `createXModule(deps)` + tests-as-spec. Enforced starting Phase 16 pilot (`hooks`).

    4. `## Consequences` — four subsections:
       - `### Positive` — LLM agents can reason about one module at a time; reversible module extraction; free causal tracing without OpenTelemetry; no ad-hoc `.catch(() => {})` Promise-chain error handling.
       - `### Negative / Costs` — 16-phase refactor (Phase 15-30); runtime parse overhead (<1ms for typical payloads); Zod+drizzle-zod version management; developers must internalise the sync-bus-vs-queue rule (lint enforces mechanically).
       - `### Constraints locked here (apply to every subsequent phase)` — bullet list:
         - Events use `noun.verbed` past-tense dotted names (enforced by `no-imperative-event-names` lint rule).
         - Envelopes use `.passthrough()` / `z.looseObject` — additive-only within a schema version.
         - Envelope field `v: z.literal(1)`; a v2 envelope is a new schema in a discriminated union, not a mutation.
         - Physical-side-effect queue jobs default to `retryLimit: 1` and `singletonKey`.
         - Graceful shutdown drains queue workers within 30s (measured on Mac Mini).
         - Node 22.12+ required by pg-boss v12.
         - `fastify-zod-openapi` + `go-jsonschema` + `openapi-typescript` codegen (Phase 17) becomes source-of-truth pipeline for CLI + web types.
       - `### Out of scope` — OpenTelemetry distributed tracing (deferred to v2 milestone); full event sourcing (current-state tables stay authoritative); multi-node pg-boss / multi-tenant / SSO (deferred).

    Each section must be at least 150 words of real prose (not just bullet dumps). Reference concrete library versions where relevant: pg-boss v12, @fastify/request-context v6, Zod 4, Drizzle ORM ^0.45.1. Reference phase numbers by title from ROADMAP.md (e.g., "Phase 17 Contracts Pipeline & Ops Hygiene", "Phase 23 Jobs Module (Keystone)").

    Target total length: 150-300 lines. Do NOT include full code blocks — short illustrative snippets only (e.g., `bus.emit('job.completed', payload)`).
