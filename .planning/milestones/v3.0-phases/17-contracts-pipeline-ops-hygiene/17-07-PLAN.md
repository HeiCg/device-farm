<objective>
Close the two remaining plugin-dep-graph gaps from Phase 17 SC5 without doing the broader rename. The verification report (17-VERIFICATION.md) identifies exactly two undeclared dependency edges where a plugin reads another plugin's decorators without declaring the dep in its `dependencies:` array:

1. **websocket → pool:** `server/streaming/websocket-plugin.ts` subscribes to `devicePreview` (a DevicePreviewManager that holds pool state) and reads device IDs at WebSocket upgrade time, but declares only `dependencies: ['config', 'auth']`
2. **api → lifecycle:** `server/api/routes.ts:439` reads `fastify.lifecycleStats` (decorated by `server/lifecycle/lifecycle-plugin.ts:33`), but `api/plugin.ts` does not list `lifecycle-plugin` in its dependencies array

Purpose: Fastify's `dependencies:` array documents the intended registration order AND (when `encapsulate: true` is set — which this project does NOT use, see RESEARCH §Pitfall 1) fails-fast at boot if unmet. Today these phantom-undeclared deps happen to boot successfully because the plugins register in the correct order for unrelated reasons, but the declaration is false. Fixing it makes the graph honest and unblocks future encapsulation work.

Scope boundary: This plan does NOT rename plugins (e.g., `pool-plugin` → `pool`). That broader normalization (the full "bare names, no `-plugin` suffix" DEBT-01 target from 17-CONTEXT.md §Plugin Naming Normalization) is deferred to a future phase. This plan only ADDS missing dependency declarations using the CURRENT registered names.

Output: Two plugin files updated with one additional dependency string each; two new invariants in plugin-order.spec.ts; no regression in existing order assertions.
</objective>
