## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Hook satisfies-check required-field list corrected**
- **Found during:** Task 3 (writing the smoke test)
- **Issue:** Plan's test example declared a Hook with `{ id, name, event, command, timeout, env, enabled, createdAt, updatedAt }` — but `hookDefinitionSchema` (server/hooks/schemas.ts) and the emitted `components.schemas.Hook` require `{ name, event, command, platform, timeoutMs, failOnError, enabled }`. No id/timeout/env/createdAt/updatedAt fields exist in the schema. The plan's `<read_first>` directive explicitly listed server/hooks/schemas.ts as required reading specifically to catch this drift ("Zod schema that produced components.schemas.Hook … verify by reading").
- **Fix:** Rewrote Hook satisfies sample with the 7 actual required fields (name/event/command/platform/timeoutMs/failOnError/enabled). Test passes; the satisfies operator locks all 7 fields as required.
- **Files modified:** web/src/lib/api/__tests__/generated-types.test.ts
- **Verification:** `npx vitest run web/src/lib/api/__tests__/generated-types.test.ts` — 4 tests pass; TypeScript compilation succeeds
- **Committed in:** 82deb95 (Task 3 commit)

**2. [Rule 1 - Bug] DeviceList test uses array-element mutual assignability instead of Pick<DeviceList, 'items'>**
- **Found during:** Task 3 (writing the smoke test)
- **Issue:** Plan's Test 3 used `Pick<DeviceList, 'items'>` — but `components.schemas.DeviceList` in the emitted file is `components['schemas']['DeviceSummary'][]` (a direct array, not an object wrapping an `items: [...]` property). `Pick<T[], K>` on an array type resolves to `Pick<Array<DeviceSummary>, 'items'>` which produces `{}` (no such field on `Array<T>`) — the test would compile to a no-op instead of a schema lock, OR `'items'` would be rejected as not assignable to `keyof DeviceList` depending on TS version, defeating the intent. openapi-typescript 7.x lowers OpenAPI `type: "array"` schemas to direct array types, matching the server's Zod `z.array(...)` shape.
- **Fix:** Replaced with two assignments asserting mutual assignability between `DeviceList` and `DeviceSummary[]` — both directions must type-check, so DeviceList becoming a wrapped object or switching its element type both break the test.
- **Files modified:** web/src/lib/api/__tests__/generated-types.test.ts
- **Verification:** Test compiles and passes; Array.isArray runtime checks pass
- **Committed in:** 82deb95 (Task 3 commit)

**3. [Rule 3 - Blocking] Root vitest include extended to discover web tests**
- **Found during:** Task 3 (running the smoke test)
- **Issue:** Root `vitest.config.ts` `include` was scoped to `server/**/__tests__/**` + `eslint-local-rules/__tests__/**` — web test file was not discovered; `npx vitest run web/src/lib/api/__tests__/generated-types.test.ts` exited with "No test files found" despite the file existing. Plan anticipated this ("If neither works, wire a minimal vitest.config.ts in web/ before running").
- **Fix:** Added two include entries to root config: `web/src/**/__tests__/**/*.test.ts` and `web/src/**/__tests__/**/*.spec.ts`. Single-root-config approach avoids split test-runner CI path; existing `npm test` now picks up web tests without changes.
- **Files modified:** vitest.config.ts
- **Verification:** `npx --no-install vitest run web/src/lib/api/__tests__/generated-types.test.ts` finds and runs 4 tests, all pass
- **Committed in:** 82deb95 (Task 3 commit)
