<objective>
Implement three parallel sub-tracks that all depend on Plan 36-01's discovery service:

1. **T-36.2 Wireless ADB pairing service** — mDNS browse (`bonjour-service`) + `adb pair` + QR generation + 60s-TTL PairingSession + cross-subnet rejection + POST/WS API surface.
2. **T-36.3 PhysicalAndroidDriver** — fills the Wave 0 stub with real adb shell-out logic; registers under `pool.registerDriver('android-physical', ...)` so adoption (Plan 36-01 Task 3) actually creates allocatable devices.
3. **T-36.6 Discovery WS** — `WS /api/devices/stream` bridges `device.discovered.*` events to web clients with replay on connect; `web/src/lib/stores/devices.svelte.ts` consumes.

Three sub-tracks share the same plan because their files are disjoint (`wireless/*`, `android/physical.ts`, `api/*`, `web stores/*`) and each is ~60-100 LOC — combining keeps Wave 2 efficient.

**Security policy:** All process spawns in this plan use `node:child_process.execFile` (argv-array form) wrapped via `promisify`. The codebase's `src/utils/execFileNoThrow.ts` helper is acceptable. Per project rules — DO NOT use the shell-string form of process spawning. PIN values are generated via `crypto.randomInt`. Subnet check rejects cross-VLAN before any shell-out. PIN TTL strictly enforced.

Output: 6 wireless service files, 1 physical driver populated, 2 API route files, 1 web store, 8 vitest specs converted from `it.todo` to real, factory wiring + driver registration.

    **mdns.ts:**
    - `browseForPairing(expectedInstance, onFound, onError)`:
      - Creates `new Bonjour()`, calls `bonjour.find({ type: 'adb-tls-pairing', protocol: 'tcp' })`
      - On `'up'` event: if `service.name === expectedInstance` AND `service.addresses` has at least one IPv4 AND `isOnLocalSubnet(ip) === true` → call `onFound(ip, service.port)`
      - On `'up'` with `!addresses?.length` (Pitfall 1 unresolved) — schedule a 500ms retry check; if still empty, drop.
      - On `'up'` with non-local subnet → `onError(new Error('Cross-subnet pairing attempt rejected: <ip>'))`
      - Returns `{ stop }` that calls `browser.stop()` + `bonjour.destroy()` (Pitfall 5 ghost-services prevention)
    - `browseForConnect(expectedGuid, onFound, onError)`: parallel — type `'adb-tls-connect'`, match by guid (from txt record or service-name suffix)
    - `isOnLocalSubnet(ip)`: walk `os.networkInterfaces()`; for each non-internal IPv4 iface, compute `(ipInt & netmaskInt) === (ifaceInt & netmaskInt)` via dotted-quad → int conversion; return true on first match

    **pair.ts:**
    - `adbPair(host, port, pin)`:
      - Spawn process with argv `['adb', 'pair', `${host}:${port}`, pin]` using argv-array helper (timeout 30_000)
      - On success: parse stdout regex `/Successfully paired to ([^\s]+) \[guid=([^\]]+)\]/` → return `{ ok: true, guid, host, port }`
      - On failure inspect stderr/message:
        - `/failed to authenticate/i` → `reason: 'auth'`
        - `/cannot resolve/i` → `reason: 'resolve'`
        - `err.killed` (timeout) → `reason: 'timeout'`
        - else → `reason: 'unknown'`

    **connect.ts:**
    - `adbConnect(host, port)`:
      - Spawn process with argv `['adb', 'connect', `${host}:${port}`]` (timeout 15_000)
      - Parse stdout `/connected to (.+)/i` → `{ ok: true, host, port }`
      - Failures: `/refused/i` → `refused`; `err.killed` → `timeout`; else `unknown`

    **qr.ts:**
    - `buildPairingQr()`:
      - `pin = String(crypto.randomInt(0, 1_000_000)).padStart(6, '0')`
      - `instance = 'devicefarm-' + crypto.randomBytes(4).toString('hex')`
      - `payload = 'WIFI:T:ADB;S:' + instance + ';P:' + pin + ';;'`
      - `dataUrl = await QRCode.toDataURL(payload, { errorCorrectionLevel: 'M', margin: 1 })`
      - Returns `{ payload, dataUrl, instance, pin }`

    **session.ts:**
    - `createPairingService({ emit, logger })` returns `{ start, get, cancel, shutdownAll }`
    - `start()`:
      - Builds QR via `buildPairingQr()`
      - Creates `PairingSession { id: randomUUID(), state: 'awaiting-scan', instance, pin, expiresAt: Date.now() + 60_000 }`
      - Stores in module-level `Map<sessionId, SessionInternals>` where internals hold mDNS browsers + state-change listeners + ttl timer + EventEmitter
      - Opens `browseForConnect(...)` FIRST (Pitfall 2 — connect-service may advertise faster than we can subscribe post-pair)
      - Opens `browseForPairing(instance, onFound, onError)`:
        - onFound: transition state to `'pairing'`, invoke `adbPair(host, port, pin)`. On `ok: true` → emit `pair.attempted` outcome `success`; stop pairing browser; the connect-browser already running picks up next event → transition state to `'connecting'`. On `ok: false` → emit `pair.attempted` outcome `auth-fail|timeout|unknown`; state = `'error'`
        - onError: emit `pair.attempted` outcome `cross-subnet`; state = `'error'`
      - Starts `setTimeout(60_000, () => session.expire())` — on expiry: stop browsers, state = `'expired'`, emit `pair.attempted` outcome `timeout`
      - When connect browser fires onFound for the same device guid: invoke `adbConnect(host, port)`; on success state = `'done'` (discovery service will pick up the new `adb devices` entry on its next 5s tick — no manual adoption needed because Plan 36-01 wired the subscriber)
    - `get(sessionId)`: returns the public PairingSession projection (without internals)
    - `cancel(sessionId)`: stops both browsers, transitions to `'error'`, emits terminal pair.attempted
    - `shutdownAll()`: iterates the map calling cancel on each — invoked by pool factory shutdown

    Session also exposes a small subscription API: `session.on('state-change', handler)` (backed by internal EventEmitter) so the WS handler in Task 3 can stream state transitions without polling.
