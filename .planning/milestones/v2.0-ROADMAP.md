## Phase Details

### Phase 10: CLI Doctor
**Goal**: User can run a single command to know exactly which dependencies are present, missing, or broken on their Mac
**Depends on**: Nothing (first phase)
**Requirements**: DOC-01, DOC-02, DOC-03, DOC-04, DOC-05, DOC-06, DOC-07, DOC-08, DOC-09, DOC-10, DOC-11, DOC-12
**Success Criteria** (what must be TRUE):
  1. User runs `device_farm doctor` and sees pass/fail status for every dependency (Java, Android SDK, ADB, Xcode, Maestro, ffmpeg, PostgreSQL, Node.js, go-ios, sim-capture, idb)
  2. Each check displays the detected version or a clear error message explaining what is missing
  3. User sees a final visual summary showing total passed vs failed checks
  4. Doctor exits with non-zero code when any check fails (CI-friendly)
**Plans**: 2 plans

Plans:
- [ ] 10-01-PLAN.md — Implement all 11 dependency check functions + unit tests
- [ ] 10-02-PLAN.md — Visual summary, exit code logic + terminal verification

### Phase 11: CLI Dependencies
**Goal**: User can run a single command to automatically install all missing dependencies detected by doctor
**Depends on**: Phase 10
**Requirements**: DEP-01, DEP-02, DEP-03, DEP-04, DEP-05, DEP-06, DEP-07, DEP-08, DEP-09, DEP-10
**Success Criteria** (what must be TRUE):
  1. User runs `device_farm dependencies` and each missing dependency is installed without manual intervention (brew, sdkmanager, official scripts)
  2. User sees real-time progress output showing which item is being installed and whether it succeeded or failed
  3. After `device_farm dependencies` completes, running `device_farm doctor` reports all checks passing
  4. Already-installed dependencies are skipped gracefully (no reinstall, no error)
**Plans**: 2 plans

Plans:
- [ ] 11-01-PLAN.md — Tests + implementation of dependencies command (installer registry, 9 install functions, orchestrator, progress, JSON output)
- [ ] 11-02-PLAN.md — Build, smoke-test, and human verification of real install behavior

### Phase 12: Device Management
**Goal**: Server manages Android emulators and iOS simulators entirely through device-stream, replacing the existing pool manager
**Depends on**: Nothing (independent of CLI phases, server-side work)
**Requirements**: DEV-01, DEV-02, DEV-03, DEV-04, DEV-05
**Success Criteria** (what must be TRUE):
  1. Server boots and shuts down Android emulators via `@device-stream/android` instead of the old pool manager
  2. Server boots and shuts down iOS simulators via `@device-stream/ios-simulator` instead of the old pool manager
  3. Device allocation remains mutex-protected and assigns one device per job without race conditions
  4. Health checks run periodically via device-stream and automatically restart failed devices
**Plans**: 2 plans

Plans:
- [ ] 12-01-PLAN.md — Install @device-stream packages, create hybrid Android driver + pure iOS driver with unit tests
- [ ] 12-02-PLAN.md — Wire new drivers into pool plugin, verify allocation/health/restart, human-verify server boot

### Phase 13: Recording
**Goal**: Every test execution produces an MP4 video recording accessible as a job artifact
**Depends on**: Phase 12
**Requirements**: REC-01, REC-02, REC-03
**Success Criteria** (what must be TRUE):
  1. Android test executions produce an MP4 recording captured via scrcpy H.264 stream from start to finish
  2. iOS test executions produce an MP4 recording captured via ScreenCaptureKit MJPEG from start to finish
  3. The MP4 artifact is associated with the job record and downloadable via the existing artifacts API
**Plans**: 2 plans

Plans:
- [ ] 13-01-PLAN.md — Refactor RecordingService to use device-stream RecordingSession + platform FrameSource
- [ ] 13-02-PLAN.md — Wire recording into job execution, expose ScrcpyService/CaptureService as decorators

### Phase 14: Fix Device Preview Pipeline
**Goal**: Device preview WebSocket delivers live frames from emulators/simulators via device-stream adapters
**Depends on**: Phase 12, Phase 13
**Requirements**: None (gap closure — closes INTG-01, FLOW-01)
**Gap Closure:** Closes integration gap INTG-01 (adapter factory missing) and flow gap FLOW-01 (preview delivers no frames)
**Success Criteria** (what must be TRUE):
  1. DevicePreviewManager has a working adapter factory that bridges ScrcpyService (Android) and CaptureService (iOS) into DeviceStreamAdapter
  2. Device preview WebSocket connects and delivers video frames to connected clients
  3. Preview heartbeat continues to work alongside frame delivery
**Plans**: 1 plan

Plans:
- [ ] 14-01-PLAN.md — Create preview adapters (Android + iOS), adapter factory, wire into DevicePreviewManager via job-plugin
